# AI 运行设计

文档版本：2026-08-07

## 当前事实

“实时教练”当前不是大模型在逐帧分析。实际链路是：

`Dota 2 GSI -> 本地字段校验/归一化 -> CoachRuleEngine -> 带证据的提醒 -> WinUI`

规则引擎处理低血量、低魔量、大招转好、阵亡、控制锁定、买活窗口、资源完整和比赛阶段变化。每条提醒包含规则 ID、触发时间和证据字段，因此不需要安装模型，也不会把对局数据上传到外部服务。

这也是当前版本更可靠的边界：GSI 快照频率高、字段有限，模型不能从不存在的字段推断敌方位置、技能冷却或购买意图。

## AI 放在什么位置

AI 只适合处理一次已经整理好的事件，例如把 `low_health` 规则改写成一句更符合上下文的建议，或在赛后根据多个时间窗口生成复盘。它不能替代规则触发，也不能直接读取原始快照来猜事实。

推荐链路：

`快照 -> 结构化特征 -> 规则结果 -> evidence -> AI 解释 -> JSON 校验 -> UI`

实时场景只在规则事件发生时调用一次，不能每个 GSI 快照都调用模型。模型超时、返回非法 JSON 或证据 ID 不存在时，直接回退到规则引擎原文。

## 模型选择

当前仓库不打包模型权重。WinUI 已提供可选的 LocalCoachService，可连接本机 Ollama：

- 云端模型：开发成本最低，需要用户配置 API 地址和密钥；默认只发送脱敏后的证据片段。
- 本机服务：默认使用 http://127.0.0.1:11434 和 qwen2.5:1.5b，页面可检测服务并通过 Ollama /api/pull 下载模型。模型由用户自行控制，仓库不打包权重。
- 嵌入式 ONNX：适合固定分类或意图识别，不适合第一版中文长文本复盘，且会增加安装包和显存/内存约束。

如果目标是离线实时解释，先使用 1.5B 级轻量模型验证延迟，再按硬件升级。当前调用超时约 800ms、输出上限 48 tokens；超时或服务不可用时保留规则原文。模型下载、许可证、升级和删除都由用户控制。

## 第一版接入约束

1. 提供 AI 开关，默认关闭；关闭或不可用时，实时教练照常工作。
2. 提供本地 endpoint、model、超时和最大输出长度设置，不把密钥写入日志。
3. 请求只携带脱敏后的 evidence envelope，不携带 token、完整 Steam ID 或未脱敏 NDJSON。
4. 返回必须通过 JSON schema、evidence_id、敏感字段和长度检查。
5. AI 输出只显示“解释”和“建议”，不执行自动购买、施法、移动、输入模拟、进程读取或 Hook。

## 验收

- 没安装模型时，实时规则提醒仍能正常显示。
- 本机服务不可用时，界面显示回退原因，不能阻塞 GSI 接收。
- 同一事件只调用一次，重复快照不会重复生成 AI 请求。
- 任意一句 AI 结论都能回溯到 evidence_id 和时间范围。
- 删除本地记录后，不再保留原始快照和 AI 报告。

## 当前版本口径

资料目录和缓存按目标版本 v7.41e 隔离，缓存文件名包含 -v7.41e。官方 datafeed 接口没有可靠的 patch 参数，因此应用不能仅凭接口响应证明线上内容已经是 7.41e；联网环境仍需用官网目录和游戏客户端实测复核。文档与界面使用“目标版本”措辞，不把它写成已验证事实。
