# AI 运行设计

文档版本：2026-08-08

## 当前事实

“实时教练”当前不是大模型在逐帧分析。实际链路是：

`Dota 2 GSI -> 本地字段校验/归一化 -> CoachRuleEngine -> 带证据的提醒 -> WinUI`

规则引擎处理低血量、低魔量、大招转好、阵亡、控制锁定、买活窗口、资源完整和比赛阶段变化。每条提醒包含规则 ID、触发时间和证据字段，因此不需要安装模型，也不会把对局数据上传到外部服务。

这也是当前版本更可靠的边界：GSI 快照频率高、字段有限，模型不能从不存在的字段推断敌方位置、技能冷却或购买意图。

## AI 放在什么位置

AI 只适合处理一次已经整理好的事件，例如把 `low_health` 规则改写成一句更符合上下文的建议，或在赛后根据多个时间窗口生成复盘。它不能替代规则触发，也不能直接读取原始快照来猜事实。

推荐链路：

`快照 -> 结构化特征 -> 规则结果 -> evidence -> AI 解释 -> JSON 校验 -> UI`

实时场景只在规则事件发生时调用一次，不能每个 GSI 快照都调用模型。模型超时、返回非法 JSON 或证据 ID 不存在时，直接回退到规则引擎原文。

## 模型选择

仓库不打包模型权重。实时教练提供三种 AI 后端，在设置页中选择：

| 后端 | 本地性能 | 说明 |
|---|---|---|
| NPU 本地推理（默认） | 极低 | OpenVINO GenAI 在 Intel AI Boost（NPU）上运行 Qwen2.5-1.5B INT4 量化模型；不占 GPU、不占用 CPU 主核。首次加载约 30 秒（仅一次），之后管线常驻，稳定态每次解释约 3.3 秒。模型目录不存在或推理失败时回退规则原文。 |
| 云端 API（OpenAI 兼容） | 零 | 只发送脱敏后的 evidence 提示词；需要用户配置接口地址、模型与 API 密钥。密钥只用于请求鉴权，不写入日志。请求超时或校验失败时回退规则原文。 |
| 规则原文 | 零 | 不调用模型，直接显示规则引擎的确定性提醒；离线也能正常工作。 |

推荐的最低占用策略是：规则事件驱动而不是逐帧调用模型；单次只发送脱敏事件和少量状态；请求间隔至少 3 秒；输出限制在 48 tokens；没有模型或推理超时时立即显示规则原文。这样实时分析仍持续运行，模型只在少数关键事件上提供补充解释。

## NPU 评估结论

NPU 适合低功耗的固定模型推理。“检测到 NPU”不等于任何运行时都会使用 NPU；本项目通过 OpenVINO GenAI 显式指定设备为 `NPU`，并只尝试 NPU/QNN/OpenVINO/VitisAI 相关的 Windows ML provider，明确跳过 DirectML、CUDA、TensorRT 和 ROCm。没有已就绪 provider 时，页面只显示 CPU 能力探测结果，不宣称已完成 NPU 推理。

对当前实时教练，NPU 不是规则判断的必要条件：GSI 快照的字段校验、差分和提醒生成在 CPU 上开销很低。NPU 的价值是把可选解释层的推理从 CPU 主核和 GPU 上移走，让游戏与系统资源保持空闲。

## NPU 推理后端（2026-08-07 实测，2026-08-08 设为默认）

- 本机硬件：Intel AI Boost（NPU），驱动 1.0.16.0；OpenVINO GenAI 运行时可识别 CPU/GPU/NPU 三个设备。
- 实现：`NpuGenAiCoachService` 使用 OpenVINO GenAI C# API 在 `NPU` 设备上运行 Qwen2.5-1.5B-Instruct INT4（OpenVINO IR，约 930 MB）。推理不占 GPU，也不占用 CPU 主核。
- 实测延迟（同一短解释提示词，管线常驻后）：NPU 首次加载含编译约 30 秒（仅一次）；后续每次约 3.3 秒（首字约 2.6 秒，约 10~13 tok/s）。
- 模型目录：`文档\AegisCoach\models\qwen2.5-1.5b-int4-ov`，模型由用户自行下载，仓库不打包权重。
- 已知限制：llmware 版 int4-ov（约 1.1 GB）在本机 NPU 编译器上报重复节点错误，不可用；通用 `OpenVINO/Qwen2.5-1.5B-Instruct-int4-ov` 可用。

## 云端后端

`CloudCoachService` 实现 OpenAI 兼容的 `/chat/completions` 调用：

- 请求只携带脱敏后的 evidence 提示词，不携带 token、完整 Steam ID 或未脱敏 NDJSON。
- API 密钥只用于 `Authorization: Bearer`，不写入日志或 `settings.json`，由 Windows 凭据保险库存储。
- 单请求超时 6 秒、串行化闸门，避免模型调用堆积影响 GSI。
- `/models` 探测用于设置页“测试云端连接”，上限 800ms。

## 第一版接入约束

1. 提供 AI 开关，默认开启；后端不可用时，实时教练照常工作并回退规则原文。
2. 提供后端选择（NPU/云端/规则）、解释间隔设置；密钥不写入日志。
3. 请求只携带脱敏后的 evidence envelope，不携带 token、完整 Steam ID 或未脱敏 NDJSON。
4. 返回必须通过 JSON schema、evidence_id、敏感字段和长度检查。
5. AI 输出只显示“解释”和“建议”，不执行自动购买、施法、移动、输入模拟、进程读取或 Hook。

## 验收

- 没安装模型时，实时规则提醒仍能正常显示。
- 本机 NPU 不可用或云端接口失败时，界面显示回退原因，不能阻塞 GSI 接收。
- 同一事件只调用一次，重复快照不会重复生成 AI 请求。
- 任意一句 AI 结论都能回溯到 evidence_id 和时间范围。
- 删除本地记录后，不再保留原始快照和 AI 报告。

## 赛后复盘（基于回放操作记录）

赛后复盘不是把聚合统计丢给模型，而是先用 `MatchOperationExtractor` 从本地 NDJSON 回放按 matchid 提取整场操作记录：

`NDJSON 回放 -> 按 matchid 过滤 -> 技能/道具使用与购买、阵亡前后决策上下文、买活、击杀与地图事件 -> 操作记录提示词 -> 模型点评`

模型被明确要求只做操作点评：不复述数据，按游戏时间指出关键道具/大招该用未用、阵亡前决策、装备节奏、买活选择，并区分事实与推断。数据不足时输出“无法判断”。

数据边界：GSI 没有英雄坐标、敌方英雄状态与视野，因此模型只能点评自身操作时机与决策（技能/道具使用时机、经济与装备节奏、死亡与买活决策），不能点评走位、视野与团战细节。本地 NPU 1.5B 适合短点评，详细长复盘建议用云端 OpenAI 兼容后端。

## 按比赛 ID 的 API 整场复盘（2026-08-08）

`MatchOperationExtractor` 依赖本机 GSI 录制；未录制或旧报告可通过 OpenDota 公开接口按 matchid 拉取整场数据：

`比赛 ID -> OpenDota /api/matches/{id} -> 定位本人玩家 -> 装备购买时间/击杀/阵亡/买活/团战/视野/经济分位/双方阵容 -> 整场数据提示词 -> 模型点评`

- 定位方式：Steam ID 64 换算 account_id；无 Steam ID 时按英雄 ID 唯一匹配。
- 数据互补：本地回放有阵亡前逐秒状态，API 有全局战局；两份数据可同时进入同一提示词。
- 边界：OpenDota 只收录公开且已解析的比赛；人机、未公开或未解析对局返回未收录，此时回退本地回放。

## 当前版本口径

资料目录和缓存按目标版本 v7.41e 隔离，缓存文件名包含 -v7.41e。官方 datafeed 接口没有可靠的 patch 参数，因此应用不能仅凭接口响应证明线上内容已经是 7.41e；联网环境仍需用官网目录和游戏客户端实测复核。文档与界面使用“目标版本”措辞，不把它写成已验证事实。
