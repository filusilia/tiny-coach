# 神盾教练核心业务规则与 UI 交互规范 (BUSINESS_RULES_AND_UI_SPEC.md)

本文档汇编神盾教练在业务计算、UI 呈现、人机交互与发布打包上的最高优先级规范。**任何后续开发与重构严禁破坏或退化已有实现**。

---

## 一、英雄模块核心业务与展示规范

### 1. 中文名称 100% 完整性兜底
- **铁律要求**：127 位英雄的中文名称（如“伐木机”、“马格纳斯”、“变体精灵”）必须 100% 正确展示，**严禁出现“待同步”或裸英文 ID**。
- **实现保障**：内置 `src/data/heroNames.ts` 静态常数表与 `public/assets/data/herostats.json`。即使断网或官方 API 数据漂移，也能毫秒级秒查中文名。
- **克制对阵列表**：对阵英雄调用 `getHeroChineseName(heroId)`，确保对阵英雄全量中文化。

### 2. 主属性判定与攻击类型
- **主属性定义**：
  - 力量 (str)：`/assets/icons/hero_strength.png`
  - 敏捷 (agi)：`/assets/icons/hero_agility.png`
  - 智力 (int)：`/assets/icons/hero_intelligence.png`
  - 全才 (all)：`/assets/icons/hero_universal.png`
- **攻击类型判定**：
  - 近战 (Melee)：`/assets/icons/melee.svg`
  - 远程 (Ranged)：`/assets/icons/ranged.svg`
- **防退化红线**：严禁出现由于空值默认分支错误导致全员跌入“全才/远程”。

### 3. Dota 2 官网原生 1 级基础属性精确公式
- **初始生命值**：$120 + \text{base\_str} \times 22$
- **生命恢复**：$\text{base\_health\_regen} + \text{base\_str} \times 0.1$
- **初始魔法值**：$75 + \text{base\_int} \times 12$
- **魔法恢复**：$\text{base\_mana\_regen} + \text{base\_int} \times 0.05$
- **初始总护甲**：$\text{base\_armor} + \text{base\_agi} / 6.0$
- **初始攻击力**：根据主属性累加到基础攻击区间（全才英雄每点三维提供 0.7 攻击力）。

### 4. 官网原生技能卡片与天赋树
- **技能卡片结构**：
  - 图标与正文：60x60 大图标、粗体白字、技能正文描述。
  - 两列通用机制：左列（施法目标 + 伤害类型色彩高亮）；右列（无视减益免疫 + 可以驱散）。
  - 阿哈利姆升级：神杖升级（金蓝卡）与魔晶升级（奥术蓝卡）展示具体赋予或强化的技能效果。
  - 先天技能：自动排在技能栏最左侧并带有先天遮罩。
- **视口稳定性**：技能切换时视口保持稳定平滑，根除视口跳顶与抖动。

## 二、物品模块核心规范

### 1. 官网式物品图鉴网格
- **顶级与子分类**：顶部切换「商店物品 / 中立物品」，子分类 Chip 多选（消耗品、属性、军备、奥术、辅助、法器、防具、武器、神器、中立 T1-T5）。
- **标准物品格**：采用 56x42 标准比例物品格（圆角 4px，鼠标悬浮 1.05 倍微缩放 + 金色描边高亮）。
- **白名单过滤**：使用现行官方物品目录过滤已移除的历史过期物品。

### 2. 悬浮详情卡片（ToolTip）
- **高对比度深色背景**：卡片必须采用深色高对比度不透明背景（`#141720`）配合高亮边框（`#405068`），严禁使用高透明度磨砂材质导致文字不可读。
- **离线合成路线解析**：内置 `item_constants.json`，离线解析每个物品的前置合成小件、数量倍数、小件单价、卷轴价格以及进阶合成装备。

## 三、UI 交互性能与防退化规范

### 1. TitleBar 专有拖拽区隔离
- 自定义标题栏中必须保留独立的拖拽区 (`data-tauri-drag-region`)；
- 标题栏搜索框与交互按钮必须严格位于普通交互区，杜绝打字穿透与窗口拖拽竞争。

### 2. IME 输入法防反弹保护
- 搜索框采用受控防抖机制，保护拼音组合输入态（Composition Event），阻止反向通知打断操作系统 IME 拼音候选。

### 3. 拼音极速检索
- 静态预加载拼音缩写（Acronym）与全拼索引表，检索时实现 0 滞后快速过滤。

## 四、离线资源与发布打包精简规范

### 1. 离线静态资源强制随包发布
`public/assets/` 下的数据与图标在构建时由 Vite 自动同步至 `dist/assets/`，确保离线状态下所有图片与资料 100% 可用。

### 2. 极轻便携分发
执行 `pwsh -NoProfile -File .\tools\package-release.ps1` 后，`release/` 目录下生成解压即可运行的免安装发布包，体积控制在 ~10MB 级别。
