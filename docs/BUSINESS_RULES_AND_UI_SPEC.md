# 神盾教练核心业务规则与 UI 交互规范 (BUSINESS_RULES_AND_UI_SPEC.md)

本文档汇编神盾教练在业务计算、UI 呈现、人机交互与发布打包上的最高优先级规范。**任何后续开发与重构严禁破坏或退化已有实现**。

---

## 一、英雄模块核心业务与展示规范

### 1. 中文名称 100% 完整性兜底
- **铁律要求**：127 位英雄的中文名称（如“伐木机”、“马格纳斯”、“变体精灵”）必须 100% 正确展示，**严禁出现“待同步”或裸英文 ID**。
- **实现保障**：内置 `frontend/src/data/heroNames.ts` 静态常数表与 `frontend/public/assets/data/herostats.json`。即使断网或官方 API 数据漂移，也能毫秒级秒查中文名。
- **克制对阵列表**：对阵英雄调用 `getHeroChineseName(heroId)`，确保对阵英雄全量中文化。

### 2. 主属性判定与攻击类型
- **主属性定义**：
  - 力量 (str)：`/assets/icons/hero_strength.png`
  - 敏捷 (agi)：`/assets/icons/hero_agility.png`
  - 智力 (int)：`/assets/icons/hero_intelligence.png`
  - 全才 (all)：`/assets/icons/hero_universal.png`
- **攻击类型判定**：
  - 近战 (Melee)：`/assets/icons/melee.svg`
  - 远程 (Ranged)：`/assets/icons/ranged.svg`
- **防退化红线**：严禁出现由于空值默认分支错误导致全员跌入“全才/远程”。

### 3. Dota 2 官网原生 1 级基础属性精确公式
- **初始生命值**：$120 + \text{base\_str} \times 22$
- **生命恢复**：$\text{base\_health\_regen} + \text{base\_str} \times 0.1$
- **初始魔法值**：$75 + \text{base\_int} \times 12$
- **魔法恢复**：$\text{base\_mana\_regen} + \text{base\_int} \times 0.05$
- **初始总护甲**：$\text{base\_armor} + \text{base\_agi} / 6.0$
- **初始攻击力**：根据主属性累加到基础攻击区间（全才英雄每点三维提供 0.7 攻击力）。

### 4. 官网原生技能与天赋一体化展台 (`AbilityShowcase.vue`)
- **一体化展台交互**：
  - 先天技能、常规技能列表与天赋树合并在单一展台中联动呈现，严禁使用 3 个分裂的卡片硬挤并排；
  - 展台顶部集成清晰的直达 Tab/技能徽章栏，点击先天技能、任一技能或天赋树，下方全景大画幅展台无缝切换展示；
  - 伤害类型、减益免疫、冷却时间与魔法消耗清晰标识；
  - 阿哈利姆神杖与魔晶强化效果具备专用展示卡片（纯中文描述，带神杖/魔晶正规图标）；
  - 天赋树展示对称的 10/15/20/25 级高对比分支树。
- **英雄简介与背景故事折叠**：
  - 官方英雄背景传记故事移至英雄简介区，默认折叠隐藏，点击按需展开，杜绝占据主屏幕纵向滚动空间；
  - 严禁出现未汉化的英文角色定位标签（Carry/Support 等须转换为中文“核心/辅助/爆发”等）及英文“Innate/Scepter/Shard”标签。

## 二、物品模块核心规范 (`ItemsView.vue`)

### 1. Dota 2 官网式物品图鉴与多层分组
- **多层级分类架构**：
  - 顶级分类：【全部物品】、【基础物品 (BASICS)】、【升级装备 (UPGRADES)】、【中立装备 (NEUTRALS)】；
  - 基础物品子分组：消耗品、属性、军备、奥术、神秘商店；
  - 升级装备子分组：辅助、法器、防具、武器、神器；
  - 中立物品子分组：第 1 阶至第 5 阶中立宝物；
  - 官网式网格分块排布：每个子分组具备专用分类标头与物品计数，下方以 56x42 标准比例方块整齐排列。
- **标准物品格**：采用 56x42 标准比例物品格（圆角 4px，鼠标悬浮 1.05 倍微缩放 + 金色描边高亮 + 悬浮金币/阶级标识）。
- **白名单过滤**：使用现行官方 7.41f 物品目录过滤已移除的历史过期物品。

### 2. 悬浮详情卡片（ToolTip）
- **高对比度深色背景**：卡片必须采用深色高对比度不透明背景（`#141720`）配合高亮边框（`#405068`），严禁使用高透明度磨砂材质导致文字不可读。
- **离线合成路线解析**：内置 `item_constants.json`，离线解析每个物品的前置合成小件、数量倍数、小件单价、卷轴价格以及进阶合成装备。

## 三、 前后端分层与桌面窗口规范

### 1. 原生窗口与极轻悬浮窗物理隔离
- **主窗口原生标题栏**：主程序窗口采用 Windows 原生沉浸式深色标题栏（`Frameless: false`），由操作系统直接接管窗口拖拽与缩放，彻底消除 Web 自定义伪标题栏的事件穿透与拖拽竞争；
- **独立置顶悬浮窗 (`OverlayView.vue`)**：局内经济 HUD 悬浮窗为独立启动的轻量置顶小窗（`Frameless: true`），作为纯只读数据战况雷达，无输入控件；已全面纯化，彻底剥离原生重合信息（头像、等级、KDA 与血蓝条），只聚焦展示【我的经济基础信息】（大号金色储备金币、GPM/XPM、实时买活监控评估）与【推荐出装】（已出装备自动隐藏不重复推荐；智能研判辅助与核心分路，辅助分路严禁推荐输出装，仅推荐大骨灰、微光、推推、绿杖、天堂等对应分路克制装）；实现极低视口遮挡与最高战术信息密度；
- **原生退出确认弹窗 (`showExitConfirmDialog`)**：当主窗口点击关闭时，若局内悬浮窗处于激活开启状态，弹出 Windows 原生模态确认弹窗，防止用户误触退出丢失悬浮雷达。

### 2. 状态流单向解耦与纯前端检索
- **清晰分层边界**：Go 后端专职处理 GSI 4444 原生网络监听、本地 TTS 模型推理与系统级调用，完全不参与前端 UI 控件渲染与键盘输入事件分发；
- **纯前端响应式检索**：英雄与物品搜索过滤由前端在内存中基于拼音与别名表响应式完成，0 跨进程 IPC 损耗。

## 四、实时教练 HUD 纯化与赛后 AI 复盘规范

### 1. 零伪造模拟数据与空态守卫铁律
- **严禁伪造任何模拟数据**：实时教练界面 (`CoachView.vue`) 与置顶悬浮窗 (`OverlayView.vue`) 严禁在游戏对局未接入时呈现任何虚拟英雄状态（如敌法师、幽鬼假数据或模拟战局）；
- **真实空态等待看板**：未连入真实对局时，必须展示清晰的“官方 GSI 4444 端口就绪，等待游戏客户端接入对局”空态指示器，绝对不伪造假战斗面板；
- **真实数据驱动**：只有收到本机 Dota 2 客户端发送的真实 GSI 快照，且 `heroId > 0`、`heroInternalName` 真实存在时，方可展开战斗 HUD。

### 2. 实时教练页 (CoachView) 战备纯化铁律
- **零配置干扰**：实时教练页面严禁出现任何系统配置开关、模拟模式选项或单选组；所有设置集中收纳于设置页 (`SettingsView.vue`)。
- **全要素战备 HUD**：
  - 核心英雄战场态：英雄大图、等级 Badge、存活/复活状态、血条/蓝条百分比动画；
  - 经济与战备雷达：K / D / A、正反补刀数、储备金币与可靠金钱、GPM / XPM、买活就绪/差额判定；
  - 技能与装备状态：技能图标与 CD 倒计时蒙层、官网 56x42 标准比例物品格（6 主物品 + 3 背包 + 中立格）；
  - 战略节拍时钟：肉山刷新窗口、痛苦魔方 20 分钟倒计时、河道强化神符刷新提示；
  - 局内独立悬浮窗：仅保留快捷唤起/关闭操作，设置项（自动弹出等）全部位于设置页。

### 3. 双引擎 AI 架构与赛后深度复盘 (`AnalysisView.vue`)
- **双引擎接入**：提供本地 Ollama 引擎（如 `qwen3.5:1.5b`，纯离线极速端侧推理）与云端 OpenAI/DeepSeek 兼容引擎，支持一键健康与延迟探测、模型列表动态拉取；
- **赛后全景复盘看板**：
  - 赛后概览：天辉/夜魇比分、胜负裁定、比赛时长与比赛编号快速检索；
  - 五维雷达图 (`RadarChart.vue`)：参战率、KDA 表现、打钱效率 (GPM)、生存能力、推塔输出；
  - 经济与经验优势走势曲线 (`AdvantageGraph.vue`)：动态还原全场对局优劣势波动节拍；
  - AI 深度复盘报告 (内嵌于 `MatchDetailPanel.vue`)：自动剖析对线期得失、团队关键节奏、核心装备质变节点与败因归因反思。

### 4. OpenDota 玩家战绩画像与脱敏合规铁律
- 接入 `api.opendota.com/api/players/{account_id}/matches?limit=25`（保留 5 场缓冲）提炼玩家近 20 场胜率、场均 KDA 与常用英雄画像；
- **合规脱敏保护**：严禁向大模型 Prompt 或日志中直接输出 Steam ID 或玩家明文标识，仅传递提炼后的风格与战术统计事实。

## 五、离线资源与发布打包精简规范

### 1. 离线静态资源与原生库强制随包发布
- `frontend/public/assets/` 下的数据与图标在构建时由 Vite 自动同步至 `dist/assets/`，确保离线状态下所有图片与资料 100% 可用；
- `lib/onnxruntime.dll` 与 `melo_weights/` 原生语音模型权重自动随包发布，确保纯离线语音合成能力。

### 2. 极轻便携分发与 release 根目录平铺
- 执行打包脚本 `pwsh -NoProfile -File .\tools\package-release.ps1` 后，**构建产物直接平铺输出至 `release/`**；
- 每次打包前自动在步骤 0 执行深度清理（清空 `release/`、`build/bin/`、`dist/` 与 `.vite` 缓存），杜绝陈旧产物残留。
