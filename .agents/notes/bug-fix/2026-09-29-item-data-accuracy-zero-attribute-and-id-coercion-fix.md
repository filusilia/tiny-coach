# Agent Note: 物品数据精准化、残存零值属性清洗、虚假 CD/MC 过滤与中文名字典类型修复

Status: implemented
Date: 2026-09-29
Class: bug-fix

## 问题背景与因果机制分析

在对物品系统与战绩界面的全景审计中，发现了以下几类严重的数据展示失真与异常现象：

1. **`gameDataService.getItemDict()` 物品中文名字典失效，战绩装备退化为英文**：
   - **因果机制**：在 `frontend/src/services/gameDataService.ts` 中构建 `itemDictCache` 时，对官方快照条目进行了类型判定 `if (val && typeof val.id === 'number' && val.id > 0)`。然而在 `items-details-official.json` 中，官方条目的 `id` 均为字符串类型（如 `"1"`、`"225"`），导致此分支全部被跳过，官方中文名称从未注入字典。最终回退使用了 `constantsJson` 中的英文名（`Blink Dagger`、`Nullifier` 等），致使比赛战绩详情（`MatchDetailPanel.vue`）中 10 位选手的 6 格装备悬浮名全部退化为英文。

2. **属性加成卡片残留历史旧版 0 增益项（如 `+生命恢复：0`、`+全属性：0`）**：
   - **因果机制**：部分经典装备（如紫怨、斯嘉蒂之眼、希瓦的守护、血精石、刷新球、否决坠饰、炎阳纹章、血棘、魂之灵瓮、战鼓、宽容之靴、行家阵列、裂隙之石、附魂面具）在经历版本平衡性重做后，官方 Datafeed 将被移除的属性数值设为 `0`（例如斯嘉蒂之眼的生命和魔法加成已被移除，改由全属性提供，但数据中仍保留 `+生命：0`、`+魔法：0`；否决坠饰保留了 `+生命恢复：0`）。前端 `parseAttributes` 简单按行切割字符串，未做数值有效性过滤，导致悬浮卡片赫然出现多项毫无意义且误导玩家的 `+xxx: 0` 条目。

3. **冷却时间与魔法消耗虚假展示为 `0s` 与 `0` 胶囊**：
   - **因果机制**：数据源中无主动冷却或无魔法消耗的物品其对应字段记录为字符串 `"0"`。在 `ItemsView.vue` 模板中直接使用了 `v-if="hoveredItem.cd"` 与 `v-if="hoveredItem.mc"`。由于在 JavaScript 中非空字符串 `"0"` 是真值（truthy），导致铁树枝干、莫尔迪基安的臂章、怪蛇之息、行家阵列等显示了 `冷却时间: 0s` 胶囊；闪烁匕首、奥术鞋、血精石、回音战刃、显影之尘等显示了 `魔法消耗: 0` 胶囊。此外，否决坠饰在数据中被误填为 `mc: "0"`（实为 75 魔耗），迈达斯之手被误填为 `cd: "0"`（实为 100 秒充能冷却）。

4. **圣化护服描述裸露未解析宏 `%AbilityCharges%`**：
   - **因果机制**：圣化护服（`consecrated_wraps`）的正文直接包含裸露占位符 `%AbilityCharges%`，破坏了界面的视觉专业度。

5. **物品商店子分类错乱**：
   - **因果机制**：`currentItemCatalog.ts` 的分类字典中，300 金币的基础小件“冰霜之珠”（`orb_of_frost`）与“远行鞋”（`travel_boots`）被错误挂载到了“神器”分类下。

## 决策方案

1. **类型兼容与官方中文名强制生效**：
   - 在 `gameDataService.ts` 的 `getItemDict()` 中，改用 `const numId = Number(val?.id); if (numId > 0)` 兼容数字与数字字符串，确保 `officialData` 中的官方中文名称 100% 覆盖并写入字典。

2. **属性加成正则清洗与 0 值过滤**：
   - 重构 `ItemsView.vue` 中的 `parseAttributes`，引入正则表达式过滤掉以 `：0`、`: 0`、`：0%`、`: 0%` 或类似结尾的零值条目；并在官方 `attrib` 为空时，从 `constantsJson` 结构化提取属性兜底，保障中立物品与基础装备的加成完整展现。

3. **冷却与魔耗有效性断言与权威修正**：
   - 实现 `hasValidCd` 与 `hasValidMc` 辅助函数，严格剔除 `0`、`"0"`、`"0.0"` 以及全为 0 的多阶字段；
   - 对官方遗漏的实战关键数值进行精准补偿：校准否决坠饰主动魔耗为 75 点，校准迈达斯之手充能冷却为 100 秒，校准圣洁吊坠充能时间为 13 秒。

4. **宏占位符补齐与分类修正**：
   - 组装物品描述时，将 `%AbilityCharges%` 精准替换为 `3`；
   - 修正 `currentItemCatalog.ts`：将冰霜之珠纠正为“军备”，远行鞋纠正为“辅助”，刷新球碎片回归肉山特殊掉落。

5. **自动化防退化测试闭环**：
   - 在 `scripts/test-hero-and-item-spec.cjs` 中追加测试 5、6、7，对字符串 ID 兼容性、零值属性过滤与分类映射实施持续集成级断言守护。

## 曾考虑的替代方案

1. **直接编辑修改本地 `items-details-official.json` 静态文件**：
   - *最强理由*：直接改写底层 JSON，上层消费逻辑无需增加任何判断。
   - *为何弃用*：`items-details-official.json` 是官方原始全量快照，保留其原始数据原貌便于与 Valve 后续更新的补丁进行自动化差异对比（Diff）；在业务消费与数据清洗层实施鲁棒的规则过滤才能保证应对未来官方 datafeed 数据抖动时的长期健壮性。

2. **直接使用 `Number(cd) > 0` 判定冷却有效性**：
   - *最强理由*：单行表达式，简单快捷。
   - *为何弃用*：Dota 2 中部分可升级物品（如达贡之神力、死灵书）的冷却和魔耗是多阶斜杠或空格分隔字符串（如 `"27 24 21 18 15"`），直接 `Number()` 会返回 `NaN`，导致多阶主动技能的冷却和魔耗全部被误杀隐藏；必须支持拆分多阶数值进行验证。
