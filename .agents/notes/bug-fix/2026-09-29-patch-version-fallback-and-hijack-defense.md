# Agent Note: 彻底禁止兜底版本号伪造、未连通置空与网络重定向拦截防御

Status: implemented
Date: 2026-09-29
Class: bug-fix

## 问题背景与因果机制分析

1. **异常现象**：
   在客户端界面（如英雄数据库头部、物品数据库分类与更新标注）中，版本号由原本官方标准规范的 `7.41f` 意外退化显示为 `7.41`，次级平衡性字母版本 `f` 丢失。

2. **完整因果链分析**：
   - **上游官方请求被本地网络安全设备拦截篡改**：
     Go 后端 `SystemService.FetchLatestPatchInfo()` 第一阶段尝试请求 Valve 官方接口：
     `https://www.dota2.com/datafeed/patchnoteslist?language=schinese`。
     在用户的网络环境下，路由器行为管理/企业防火墙（如 1.1.1.2 审计设备）将 `dota2.com` 识别为“游戏/刀塔”，发出 HTTP 302 强制重定向至 `http://1.1.1.2/disable/disable.htm?url_type=游戏/刀塔`，返回 HTML `<h2>Moved</h2>`。原代码中 `http.Client` 默认跟随重定向至该内网地址，且未过滤 `Content-Type: text/html`，导致 JSON 解码失败，阶段 A 官方数据拉取中断。
   - **OpenDota 降级源本身仅维护主版本号**：
     官方接口失败后，系统降级请求 OpenDota API：`https://api.opendota.com/api/constants/patch`。
     OpenDota 该接口的权威事实：**其终点站仅收录整数大版本（Major Patches，如 7.39, 7.40, 7.41），绝不收录字母平衡性补丁（7.41a ~ 7.41f）**。其返回数组的最后一项为 `{"name": "7.41", ...}`。
   - **比较机制缺少精度保护，粗粒度主版本冲刷细粒度小版本**：
     原代码直接执行 `latestVersion = validOd[len(validOd)-1]`，把 `latestVersion` 赋值为 `"7.41"`。
     若使用固定版本硬编码兜底（如强行替换为 7.41f），不仅破坏了零伪造原则，还会掩盖真实的获取故障。

## 决策方案

1. **彻底禁止任何兜底版本号，未获取到直接置空 (零伪造铁律)**：
   - 若 Valve 官方接口与 OpenDota 接口因网络断开、超时或被防火墙拦截而未能获取有效数据，版本号严格置空 `""`；
   - 彻底剔除前后端任何 `fallbackVersion = "7.41f"` 或 `|| '7.41f'` 的假数据伪造行为，真实反馈网络与版本状态；
   - 前端各视图组件在版本号为空时优雅展示空态或等待连接，绝不强行展示虚假的默认版本。

2. **网络重定向与劫持拦截防御**：
   在 Go 后端 `http.Client` 中配置：
   - `CheckRedirect` 钩子：当重定向目标域名非 `dota2.com` 或 `valvesoftware.com` 时，立即终止跟随重定向（返回 `http.ErrUseLastResponse`），彻底阻断被内网防火墙（如 1.1.1.2）劫持；
   - 增加 `Content-Type` 强校验：严禁将 `text/html` 的网页内容当做 API 数据解析；
   - 历史缓存读取时实事求是返回，绝不擅自脑补。

## 被否决的备选方案论证

### 方案 A：在后端或前端强行将 "7.41" 或空值兜底升格为 "7.41f"
- **最强理由**：实现极其简单直接，在断网或 OpenDota 仅有大版本时依然能展示看起来“完整专业”的 `7.41f`。
- **为什么不采纳**：严重违反了《AGENTS.md》开工铁律第 8 条（零伪造原则）以及用户明确要求（“禁止任何兜底版本号等行为，没有网络或访问不到时直接置空”）。当网络异常或接口受限时，伪造版本号会让用户误以为网络正常、数据是最新的，掩盖真正的通信阻断问题，必须实事求是置空。
