# Agent Note: 悬浮窗锁定交互解耦、三级数据缓存管线、动态补丁日志与技能专属Tips集成

Status: implemented
Date: 2026-09-22
Class: bug-fix

## 问题背景与因果机制分析

1. **悬浮窗点击“锁”导致全部功能失效陷入死锁**：
   - **因果机制**：此前在悬浮窗标题栏放置的切换按钮直接绑定了 `setIgnoreMouseEvents(true)`。在 Windows 系统底层，该调用会为整个 HWND 窗口追加 `WS_EX_TRANSPARENT` 样式。该样式的 Win32 语义是将所有 `WM_NCHITTEST` 与鼠标点击事件穿透到底层窗口（Dota 2 或桌面），导致悬浮窗自身的 WebView2 客户区**完全无法接收到任何鼠标事件**。
   - **致命后果**：用户点击“锁”之后，由于鼠标事件无法再到达按钮，既无法再次点击按钮解锁，也无法点击关闭按钮 `X`，更无法拖拽窗口，形成完全不可恢复的交互死锁状态。
   - **认知混淆**：在电竞游戏 HUD 交互规范中，“标题栏锁”通常是指“锁定窗口拖拽位置（Lock Position）”，防止对局激烈甩鼠标时误拖拽；而“点击穿透（Click-Through）”属于全局 HUD 观战特性，应通过全局热键或菜单独立受控。

2. **数据缓存文件夹为空与图鉴数据未落盘**：
   - **因果机制**：此前前端视图（`HeroesView`、`ItemsView`）仅静态 `fetch('/assets/data/...')` 打包在应用内的基线文件；Go 端 `SystemService.CacheAllIcons` 仅扫描本地目录统计文件数量，从未实际发起过 HTTP 下载；Go 端亦缺少读取/持久化结构化游戏数据（`herostats.json`、`items.json`、`patch_info.json`）的 IPC 接口，导致用户配置的本地缓存文件夹始终处于空态。

3. **写死 7.41e 热门与兜底虚构英雄违背零伪造铁律**：
   - **因果机制**：此前在代码中多处硬编码了 `"当前 7.41e 热门"`、以及在未发现更新时硬编码虚拟新英雄列表 `[131, 145]`。这直接违背了《开工铁律》第 8 条（零伪造原则）以及用户明确要求。
   - **技能 Tips 排版缺陷**：英雄技能专属小技巧（如敌法师「法力损毁」点人拉仇恨、「法术反制」抬手反弹、「法力虚空」已损魔法斩杀）此前混杂在整个页面最底部的通用大列表里，未能直接放在对应技能卡片中呈现。

## 决策方案

### 1. 悬浮窗交互行为彻底解耦
- **标题栏锁 = 锁定窗口位置（`isPositionLocked`）**：
  - 按钮采用 `<Lock>` 与 `<Unlock>` 图标切换。
  - 锁定状态下，禁用原生拖拽（`--wails-draggable: none`，拖拽回调拦截），光标为默认指针；但**窗口上的解锁、折叠、关闭按钮保持 100% 可点击交互**，绝不阻塞用户操作。
- **鼠标穿透模式 = 全局热键 `Alt+F3` 独占控制**：
  - 仅由全局热键 `Alt+F3`（或托盘/设置菜单）触发 Win32 穿透；
  - 穿透开启时，悬浮窗顶部浮现明显的呼吸指示横幅：`已开启鼠标穿透 (按 Alt+F3 解除)`，用户随时清楚如何恢复鼠标控制。

### 2. 三级数据缓存与统一数据服务（`GameDataService`）
- **Go 端基础设施**：
  - 在 `SystemService`、`App` 暴露 `LoadCachedGameData(dataType)` 与 `SaveCachedGameData(dataType, content)`，将数据持久化至 `<cacheDir>/data/<dataType>.json`。
  - 重写 `CacheAllIcons`：并发扫描并从官方 CDN 拉取英雄头像与物品图标至 `<cacheDir>/heroes/` 与 `<cacheDir>/items/`，实现真实落盘与预热。
- **前端三级调用链**：
  - **优先级 1 (本地磁盘缓存)**：优先调用 `LoadCachedGameData`，命中则直接解析返回，实现零网络开销、毫秒级加载。
  - **优先级 2 (网络请求与落盘)**：本地缺失时，异步请求官方或 OpenDota API（`https://api.opendota.com/api/heroStats`、`https://www.dota2.com/datafeed/patchnoteslist`、`https://www.dota2.com/datafeed/patchnotes`），成功后原子化写入本地磁盘缓存目录。
  - **优先级 3 (报错与兜底)**：网络请求异常且无本地磁盘缓存时，严格弹出全局 Toast 错误通知用户（`useAppStore().showToast(...)`）；同时使用打包基线资源保障应用免于白屏崩溃。

### 3. 技能专属 Tips 直接嵌入技能卡片
- 在 `HeroesView.vue` 建立智能关联算法 `isTipRelatedToAbility`，根据技能中文名、英文关键字自动命中对应技能。
- 选中的技能卡片内直接呈现：
  1. **技能专属实战技巧与机制要点**（来自 OpenDota / 精选指南）；
  2. **官方技能机制深入注解**（来自 `notes_loc`）；
  3. **现行补丁版本调整日志**（来自官方 Patch Notes）。
- 底部仅保留宏观战略要领（`generalHeroTips`），杜绝重复冗余信息。

### 4. 动态版本号与真实补丁更新标签（零伪造）
- 彻底剔除所有写死的 `"7.41e"` 字符串，统一使用响应式 `currentPatch`（如 `v7.41f`）。
- 严格解析最新官方 Patch Notes：
  - 仅在最新补丁中确实有数值/机制改动的英雄上展示 `v{{ currentPatch }} 更新` 徽标；
  - 未发生改动的英雄严禁显示更新标签；
  - 彻底移除 `dataSyncService` 中的兜底虚构英雄列表，坚决杜绝任何假数据。

## 曾考虑的替代方案

### 替代方案 A：在鼠标穿透模式下通过透明区域或按键倒计时自动解除
- **最强理由**：如果用户误开了穿透，5 秒无操作后自动退出穿透，可以防止用户不知道按快捷键而困住。
- **为什么不用**：游戏内玩家处于激烈团战时，悬浮窗如果因为 5 秒倒计时突然恢复为阻挡鼠标的普通窗口，玩家点击地图或技能恰好点在悬浮窗上，会导致游戏指令完全丢失、英雄原地暴毙，产生极其灾难的作弊/打扰体验。因此必须严格遵循电竞 HUD 原则：穿透只由明确的全局热键 `Alt+F3` 决定，标题栏按钮仅负责位置锁定。

### 替代方案 B：纯前端使用 IndexedDB / localStorage 替代磁盘文件缓存
- **最强理由**：纯前端 API，不需要修改 Go 后端与 Wails 绑定，开发成本最低。
- **为什么不用**：
  1. 用户在“设置”页面配置了本地数据存储路径（例如用户指定的文档盘或移动硬盘），用户的诉求是“打开文件夹能看到数据落盘”，IndexedDB 存储在 WebView2 的浏览器内部 AppData 中，用户在 Explorer 中完全看不见，无法实现离线备份、迁移模型和多实例共享；
  2. Wails v3 多窗口架构下，主窗口与独立悬浮窗属于不同进程，统一由 Go 后端在指定磁盘目录读写结构化 JSON 更加可靠稳健。

## 后果与验证计划

### 正面收益
- 悬浮窗锁定体验完美解耦，用户再也不会遇到“点击锁后全部失效无法解锁”的困境；
- 用户指定的缓存文件夹能够完整看到 `heroes/`、`items/` 与 `data/` 下的数据文件，缓存可用性 100% 成立；
- 英雄与装备更新信息由官方实时补丁驱动，信息真实、完整、权威；技能专属 Tips 一览无余，显著提升玩家选英雄时的查阅效率。

### 验证计划
1. 运行 `npm run verify-notes`：校验全量 Agent Notes 结构格式；
2. 运行 `pnpm build`：确保前端全量打包编译通过；
3. 运行 `pwsh -NoProfile -File ./tools/package-release.ps1`：执行发布包构建，确保二进制产物正常生成。
