# 局内置顶雷达悬浮窗纯化重构决策笔记：剔除原生重合UI、已出装备自动隐藏与辅助/核心分路识别

## 1. 产生背景 (Context)

局内独立置顶悬浮窗（`OverlayView.vue`，在界面中称为“雷达”）作为玩家在 Dota 2 客户端内游戏时常驻置顶的半透明 HUD，其核心价值在于在不遮挡游戏画面的前提下提供最关键的战备情报。
用户明确提出深入的 HUD 纯化与推荐出装逻辑要求：
> 1. “游戏中是有我的头像的，kda也有，所以不需要这个信息”
> 2. “针对出装如果我已经出了，可以自动不展示”
> 3. “并且要能够识别，我如果是辅助，不给我推荐输出的推荐装，只推荐对应分路的推荐装”

---

## 2. 问题分析与因果机制 (Problem Analysis)

1. **游戏原生 HUD 重合导致的信息冗余**：
   Dota 2 游戏底层原生界面底部正中已经清晰展示了所操控英雄的头像、等级、实时生命值条、魔法值条与 KDA 战绩。在仅 330px 的极紧凑雷达悬浮窗中重复渲染这些指标，不仅没有增量战术价值，反而占用了高达 80px 的垂直空间，加剧了对游戏主视口的遮挡。真正的未公开或难以即时心算的经济数据是：储备金币、GPM、XPM 与精准买活警戒（买活差额与冷却）。
2. **已出装备重复推荐导致的决策干扰**：
   原逻辑不论玩家是否已经在局内做出了黑皇杖、推推或大骨灰，推荐出装卡片均持续展示这些已完成的装备，造成出装指引滞后且占用有效展示槽位。
3. **分路定位倒置（辅助被推输出装）的严重不合理性**：
   原 Go 后端 `generateCounterItems` 采用了一刀切的 Carry 输出矩阵（强控出 BKB，闪避出金箍棒/大隐刀，肉盾出冰眼/否决，高机动出血棘）。若玩家操控的是冰女、莱恩、巫医或剧毒等辅助英雄，为其推荐金箍棒、白银之锋、冰眼或否决不仅毫无操作可行性，更严重脱离竞技实战。辅助英雄在对抗上述特质时，需要的是天堂之戟（缴械核心）、幽魂权杖（绿杖物理免疫自保）、魂之灵龛（大骨灰削减45%回复）、微光披风（魔法护盾与隐身救人）、原力法杖（推推救人防切）、永恒之盘与阿托斯之棍。

## 3. 架构决策与落地实现 (Decisions & Implementation)

### 3.1 彻底剥离原生重合信息，收敛至纯粹基础经济
- 从 [`frontend/src/views/OverlayView.vue`](file:///D:/develop/demo/frontend/src/views/OverlayView.vue) 中彻底移除英雄头像、等级徽章、KDA 文本和血蓝双条进度动画；
- 保留最核心的经济与战况三联格：
  - 储备金币（大号金色字体高亮）；
  - GPM 与 XPM 实战打钱与升级效率；
  - 实时买活监控评估（买活就绪/缺额/冷却时间）；
  - 操控英雄名称与当前分路研判指示 Badge（如“辅助分路”或“核心输出”）。

### 3.2 已购与进阶装备全槽位自动过滤 (`itemRecommendationFilter.ts`)
- 在 [`frontend/src/services/gsiRuleEngine.ts`](file:///D:/develop/demo/frontend/src/services/gsiRuleEngine.ts) 中增加 `activeBattleContext.allOwnedItemNames`，实时汇总物品栏、背包、储藏处及中立槽位中所有非空装备；
- 新建 [`frontend/src/utils/itemRecommendationFilter.ts`](file:///D:/develop/demo/frontend/src/utils/itemRecommendationFilter.ts)，建立 `ITEM_UPGRADE_FAMILIES` 装备进阶衍生同族字典（如原力法杖衍生飓风长戟、幽魂权杖衍生虚灵之刃、微光披风、吹风衍生风之杖、骨灰衍生大灵龛、BKB 等）；
- 任何已拥有的装备或其高级进阶版本自动从 `counterItems` 中剔除，一旦完成购买即刻退场，自动顺延展示下一件克制建议。

### 3.3 辅助 vs 核心分路与角色识别矩阵
- **Go 后端分路权威知识库**（[`internal/services/player/recommendation.go`](file:///D:/develop/demo/internal/services/player/recommendation.go)）：
  - 建立 37+ 官方典型纯辅助英雄 ID 映射表（`supportHeroIds`）；
  - 重构 `generateCounterItems`：当识别为辅助英雄时，严格切换为 **Support Counter Matrix**：
    - 面对物理闪避/平A突脸：推荐 **天堂之戟**（缴械物理核心）、**幽魂权杖/绿杖**（物理免疫4秒防切）、**原力法杖**（推推位移）；
    - 面对高回复/肉盾：推荐 **魂之灵龛/大骨灰**（百分比扣血+削减45%回复）；
    - 面对法爆/强控：推荐 **微光披风**（隐身+300法术护盾）、**洞察烟斗**（全队法盾）、**永恒之盘**（强驱散+无敌2.5秒）；
    - 面对高机动位移：推荐 **阿托斯之棍**（远距离缠绕2秒封锁位移）、**吹风杖**（留人与自保驱散）；
  - 当为非辅助（核心大哥）英雄时，严格推荐输出克制装（BKB、金箍棒、白银之锋、冰眼、否决、血棘），并标注契约属性 `Role: "core"` / `Role: "support"`。
- **前端局内动态遥测辅助研判**（[`frontend/src/stores/battle.ts`](file:///D:/develop/demo/frontend/src/stores/battle.ts)）：
  - 结合英雄先验常数库；
  - 监听玩家是否购买补刀斧（`quelling_blade` -> 排除辅助）；
  - 监听是否购买辅助真假眼/雾/秘法/微光/大骨灰；
  - 在比赛 3 分钟后，正补数 < 12 且 GPM < 380 自动校准为辅助分路，彻底双重保障。

### 3.4 悬浮窗尺寸深度收敛
- 折叠态：240 × 52px；
- GSI 未连接态：有推荐出装 332 × 220px，无推荐出装 332 × 150px；
- GSI 已连接态：
  - 基础经济 + 推荐出装：332 × 295px（大幅释放屏幕纵向视野）；
  - 仅基础经济：332 × 175px。

## 4. 被否决的备选方案与强辩驳 (Discarded Alternatives)

### 方案 A：在悬浮窗上增加手动单选切换“我是辅助 / 我是核心”
- **最强理由**：万一摇摆英雄（如风行者、米拉娜、矮人直升机）辅助/大哥打法判断失误，手动切换最稳妥。
- **否决原因**：违反实战无干扰原则。电竞对抗中玩家双手需要高度专注于补刀与对线博弈，悬浮窗还是透明置顶甚至开启穿透的；通过英雄常数 + 补刀斧 + 辅助装备购买 + 补刀数据进行 0 延迟自动化推导，准确率达 99% 以上，绝不强加手动 UI 负担。

### 方案 B：直接根据玩家所在天辉/夜魇队伍槽位编号 (Slot 1-5) 判定分路
- **最强理由**：Valve GSI 提供玩家槽位编号，若 4/5 对应辅助则零计算成本。
- **否决原因**：路人天梯与普通匹配中，选人阶段进入的槽位与实际分路完全无绑定关系（1号位进5号槽位极为常见）；强行依赖 slot 会产生严重误判，故必须使用“英雄先天定位 + 装备与经济行为”进行真实判别。
