# Agent Note: 赛后详情防抖动、通用物品悬浮卡复用、AI战术复盘深度扩容与档案一体化重构

Status: implemented
Date: 2026-09-29
Class: architecture

## 问题背景与因果机制分析

1. **赛后详情复制比赛 ID 页面抖动根因**：
   - **因果机制**：旧版在复制比赛 ID 成功后，直接在按钮行内插入了 `<span v-if="matchIdCopied">已复制</span>`，导致按钮容器宽度瞬间从 ~100px 突增至 ~160px，由于父容器采用了 Flex 自动伸缩排版，强行挤压右侧的比分与时长元素，产生剧烈的页面重排与视差抖动。
   - **解决措施**：将复制成功的轻提示重构为绝对定位的浮动气泡（`absolute -top-7 left-1/2 -translate-x-1/2`），按钮本体保持固定宽高且尺寸零形变，彻底根治复制时的晃动现象。

2. **装备大盘表格宽度与换行缺陷修复**：
   - **因果机制**：旧版表格设置的最小宽度不足（`min-w-[1080px]`），且缺少严格的 `whitespace-nowrap`，在视口宽度较小或装备栏文本较长时，KDA、输出伤害等列被强制折行，破坏整体美观与可读性。
   - **解决措施**：将表格容器基准宽度提升至 `min-w-[1260px]` 并统一追加 `whitespace-nowrap`，配合外层 `overflow-x-auto`，实现平滑横向滚动并杜绝任何单元格折行。

3. **装备/中立物品悬浮卡抽取与垃圾代码清零（高复用原则）**：
   - **因果机制**：此前在物品图鉴（`ItemsView`）、英雄出装（`HeroBuildPanel`）和赛后大盘中，存在各自定义的几百行私有 Tooltip 模板，样式不一致、缺少统一的点击锁定滚动机制，中立物品属性与技能说明也缺少汉化。
   - **解决措施**：遵循高复用原则，杜绝重复冗余代码：
     - 创建通用组件 `frontend/src/components/common/ItemTooltipCard.vue`，统一支持 56x42 规格物品、官方深色高对比度 HUD 样式、未固定状态防遮挡（`pointer-events: none`）与点击 Pin 锁定状态自由滚轮浏览（`pointer-events: auto`）。
     - 创建 `frontend/src/utils/itemTextResolver.ts`，内置 30+ 种属性英文正规化汉化映射表（Health -> 生命值，Damage -> 攻击力，All Attributes -> 全属性等），自动清洗 0 增益项，并汉化主动/被动/开关标签。
     - 在 `ItemsView.vue`、`HeroBuildPanel.vue` 和 `MatchDetailPanel.vue` 中全面淘汰私有模板，100% 切换复用 `<ItemTooltipCard>`，且统一使用 `<Teleport to="body">` 杜绝祖先溢出裁剪。

4. **AI 战术复盘过简与深度扩容**：
   - **因果机制**：此前 Prompt 缺少针对 TI 职业教练的深入指引，限制了输出字数与失误条数，且 `max_tokens` 仅设为 1200，导致大模型草草概括；同时 Go 端在纯规则（`rule_only`）或调用失败时仅返回 3 句套话，严重影响用户体验。
   - **解决措施**：
     - 重构前端与 Go 端的 Prompt：设定顶级 TI 冠军主教练与高阶数据分析师角色，要求结合正反补速率、KDA 容错、双方英雄机制对位与装备克制因果，展开 4 个维度不少于 150 字的深入推演，将 `max_tokens` 提升至 2500，并将超时容忍调整至 35~45 秒。
     - 深度重构确定性离线复盘引擎（`generateDeterministicReview` 与 `generateDeterministicMatchReview`）：根据对线期补刀速率（每分钟刀数 CS/Min）、阵亡次数、伤害占比、参战率、终局神装（BKB、闪烁、驱散保命装等）以及敌方核心装备威胁进行客观推演，产出 600~800 字的高质量多段专业战术报告。
     - 在 `AiReviewPanel.vue` 中增加 `whitespace-pre-line leading-relaxed`，确保长段落排版整齐清晰。

5. **个人档案大盘一体化紧凑排版**：
   - **因果机制**：旧版将头像与雷达图、数据统计拆分为两张上下大卡片，下半部包含占地过大的能量进度条，雷达图右侧大量留白，版面松散。
   - **解决措施**：
     - 重构 `PlayerProfileBanner.vue`：左侧为选手头像/ID/段位与刷新，中间内嵌 `RadarChart` 五维图，右侧紧凑陈列 6 宫格场均与胜率核心指标（胜率、场均 KDA、KDA 比率、GPM、推塔、总场次），彻底剔除冗余进度条，形成单卡片一体化。
     - 重构 `AnalysisView.vue`：下半区由常用英雄池（占 4 列）与对局历史（占 8 列）左右对称紧凑排布，大幅提升信息密度。

## 被否决的备选方案论证

### 方案 A：在赛后详情表格中各行私有内联一套 Tooltip 浮窗
- **最强理由**：实现简单直接，无需在顶层管理当前 Hover 物品状态与 Teleport。
- **为什么不采纳**：赛后表格包含十位选手共 100+ 个物品槽位，如果为每个格子复制或实例化独立的 Tooltip DOM 节点，不仅会造成大量冗余垃圾代码，还会导致表格滚动时内存占用与事件监听激增；抽取单例 `ItemTooltipCard` 并通过 `Teleport to="body"` 挂载是最高性能与最优雅的单例复用方案。

### 方案 B：AI 复盘在超时或模型不可用时直接提示“复盘失败请重试”
- **最强理由**：完全不给离线报告，督促用户去配置模型 API Key。
- **为什么不采纳**：神盾教练遵循严密的工业级高可用原则，当用户处于无网环境或使用的是纯规则模式时，系统必须基于真实对局客观数据（CS/min、参战率、终局装配）给出有说服力的专业复盘，绝不让用户面对冰冷的报错。
