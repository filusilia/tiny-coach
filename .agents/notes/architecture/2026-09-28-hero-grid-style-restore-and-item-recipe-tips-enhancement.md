# Agent Note: 英雄图鉴列表大图样式恢复与物品页技能标签/配方图纸/机制提示强化

Status: implemented
Date: 2026-09-28
Class: architecture

## 问题背景与因果机制分析

在日常对局查阅与装备图谱使用中，用户针对英雄与物品模块提出了核心体验反馈：

1. **英雄列表视觉体验退化**：
   - 此前重构中，为提高屏占比将首页 127 英雄列表压缩成了密集的小方格（10~12 列），导致英雄封面过小、信息层级挤压。用户期望只恢复之前的英雄列表展示样式（400x250 大图、渐变底色、左上属性图标、右上有机胜率与底部中文字号），同时保留英雄详情展台的单页化解耦成果。

2. **物品资料页视觉噪音与技能标签错位**：
   - 物品资料页的 56x42 图标格子上此前叠加了“主”、“被”以及售价微型标签，破坏了 Dota 2 官网物品图鉴原生的纯粹美感；
   - 悬浮卡片顶部标题右侧直接放置了粗粒度的“主动技能”或“被动技能”标签，不仅无法区分多技能装备（如刃甲既有主动又有被动），且占用标题行空间；真正的技能描述区域却使用纯平铺文本，失去了官网“主动：技能名 / 被动：技能名”的层次感。

3. **合成配方图纸缺失与价格断层**：
   - 物品详情组件此前直接读取 OpenDota `item_constants.json` 的 `components` 字段，而该字段缺失了全部 `recipe_xxx` 图纸（共 93 个大件缺图纸）；
   - 官方中文数据 `items-details-official.json` 虽然包含带图纸的 `requirements`，但未在视图层解析，且 `getComponentItem` 仅从已过滤的商品字典查找，导致图纸被当做未知件显示为“0 金 / 合成卷轴”，黑皇杖等装备配件总价与售价严重脱节；部分装备（如玲珑心缺少灵魂之球、怪蛇之息图纸标价）亦存在版本细微偏差。

4. **官网机制提示（如蝴蝶非线性叠加）未呈现**：
   - 官方快照中包含 101+ 个装备的独家机制注释（`notes`，例如蝴蝶“与其他闪避效果为非线性叠加。”、黑皇杖“再次购买不会重置持续时间”、深渊之刃“凯双钗模式无法触发”等），此前视图层完全未予渲染，造成高阶战术信息缺失。

## 决策方案

### 1. 英雄列表大卡片样式精准恢复
- 保持 `HeroStatsCard`、`AbilityShowcase`、`HeroBuildPanel` 详情展台架构不变；
- 英雄列表网格由密集小格恢复为官方经典布局（`gap-4 grid grid-cols-2 2xl:grid-cols-7 lg:grid-cols-5 md:grid-cols-4 sm:grid-cols-3 xl:grid-cols-6`）；
- 恢复 16:10 英雄大图、渐变阴影底色、左上主属性图标（力/敏/智/全）与版本更新徽章、右上胜率胶囊、底部英雄中文大名与场次。

### 2. 物品图标列表极简降噪与技能描述细粒度标签化
- **图标网格清理**：移除方格上的“主”、“被”与售价角标，保持官网 56x42 原生视觉；
- **顶部标题降噪**：悬浮卡片顶部标题行彻底移除“主动技能 / 被动技能”全局标签；
- **技能多段解析与微标签**：实现 `parseItemSkills(desc)`，识别 `主动`、`被动`、`开关`、`使用` 等技能段落，为每个独立技能赋予独立彩色微标签（如琥珀金“主动”、翡翠绿“被动”、青色“开关”），并突出展示技能名称与具体效果。

### 3. 配方图纸双向补全与价格对齐
- **配方源切换**：配件列表优先消费官方 `raw.requirements`，剔除末尾星号 `*` 与空字符串；
- **全量图纸字典**：维护包含所有 `recipe_xxx` 的权威物料字典，准确注入图纸官方中文名（如“图纸（黑皇杖）”）、真实售价（如 1450 金）与官方卷轴图标；
- **版本特殊补正**：对照 7.41f / Liquid 补全玲珑心（`soul_booster` 3000 金）、天堂之戟图纸（350 金）与怪蛇之息图纸（1000 金），使全量升级装备配件金额与标价 100% 对齐。

### 4. 官网高阶机制提示（Notes）卡片渲染
- 在悬浮卡片中新增机制提示专属卡片，只要 `hoveredItem.notes` 存在即予渲染，支持官方 HTML 实体清洗，完整传递蝴蝶、黑皇杖、幻影斧等核心机制说明。

## 曾考虑的替代方案

1. **方案一：在原生 JSON 文件中硬编码改写所有装备配方**
   - *最强理由*：改动集中在静态数据，无需写前端解析逻辑。
   - *为什么不用*：`items-details-official.json` 是官方 datafeed 快照，直接手工改动会导致后续数据同步时被覆盖；在前端视图层进行规范化解析与补正，更加透明且符合“单一事实来源 + 派生解析”原则。

2. **方案二：保留卡片顶部的主动/被动标签，同时在正文也加上**
   - *最强理由*：双重提示最醒目。
   - *为什么不用*：多技能装备（如刃甲兼具主动与被动、雷神之锤兼具主动与被动）在顶部放双标签极其拥挤杂乱，且违背用户明确提出的“去掉主动技能标签，被动技能标签，将技能描述的主动，被动增加技能标签”要求。
