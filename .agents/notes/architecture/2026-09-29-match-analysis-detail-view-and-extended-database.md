# Agent Note: 赛后复盘独立详情页重构、全景战报数据库扩展与 AI 战术研判升级

Status: implemented
Date: 2026-09-29
Class: architecture

## 问题背景与因果机制分析

1. **单页长列表堆叠导致的体验割裂与视线焦点迷失**：
   - **因果机制**：
     - 原 `AnalysisView.vue` 采用全单页堆叠结构，顶部为搜索框与玩家画像雷达图，中间为近期比赛列表，点击后将十人全景大盘和 AI 复盘报告追加在页面最下方；
     - 导致整页高度剧增（动辄数千像素），用户在点击比赛后必须长时间向下滚动查找内容，且无法在沉浸式的全屏环境中专注研读单局对局；
     - 缺乏“列表总览 ⇄ 单场独立详情”的明晰页面层级流转与面包屑导航，不符合主流电竞战绩产品（如 Dotabuff、OpenDota、客户端战绩）的使用习惯。

2. **对局数据库指标深度不足，无法满足高阶复盘需求**：
   - **因果机制**：
     - 原 `MatchDetailPanel` 仅渲染了 6 格神装 + 1 格中立装备与基础 KDA、伤害、GPM、正反补；
     - **缺失背包 3 格 (`backpack_0~2`)**：导致飞鞋、跳刀、真假眼、刷新碎片等暂存物品无法被看到；
     - **缺失关键实战数据库**：如 XPM (每分钟经验)、推塔推进伤害 (`tower_damage`)、英雄治疗量 (`hero_healing`)、插眼真假眼视野贡献 (`sen_placed`/`obs_placed`)、拉野堆叠数 (`camps_stacked`)、控符数 (`rune_pickups`)、买活次数 (`buyback_count`)；
     - **缺失战术走势核心资产**：OpenDota 的 `radiant_gold_adv` 与 `radiant_xp_adv`（每分钟团队经济与经验差走势）未被可视化，用户无法直观洞察翻盘分水岭与转折时刻；
     - **缺失阵容 BP 禁选数据**：没有按顺位展示双方 Ban / Pick 顺序。

## 决策方案

### 1. 独立比赛深度详情页与双向流转架构
- **路由与页面分层**：
  - 在 `router/index.ts` 中注册 `/analysis/match/:id` 路由，并与 `AnalysisView` 保持统一的 `tab: 'analysis'` 侧边栏高亮；
  - 既支持在近期比赛列表点击条目或搜索框回车秒级进入详情页，也支持外部链接或刷新后按 ID 精准直达；
  - 详情页配备顶部导航栏：【← 返回比赛列表】按钮、`战局复盘 / 比赛 #7987654321` 面包屑与快捷刷新/复制功能。

### 2. 核心 AI 深度复盘战术研判中心置顶
- 详情页顶部集成醒目的 AI 战术教练控制台：
  - 自动识别当前登录玩家并默认高亮其视角，同时支持一键切换十人中任意一位选手；
  - 呈现主视角英雄、昵称、KDA、GPM/XPM、净资产与胜负状态；
  - 【启动 AI 深度复盘】按钮与实时思考动画，支持一键调用本地 NPU / 云端大模型 / 确定性规则引擎；
  - 结构化四分块报告呈现：大盘胜负定局、视角实战得失、装备针对性克制、下局提升指南，并支持一键复制完整文本。

### 3. 多维度战报数据库扩展（4 大专业 Tab）
- **Tab 1: 【阵容与全装大盘】(Overview & Full Items)**：
  - 天辉 vs 夜魇双方十人完整卡片，展示 6 格主装 + 3 格背包 + 1 格中立装备 + A 杖与魔晶徽章；
  - 呈现 KDA、参战率 (KP%)、净资产、总金币、GPM、XPM、英雄伤害 (含团队伤害占比可视化条)、推塔伤害、英雄治疗量、正反补。
- **Tab 2: 【团队经济与经验走势】(Advantage Graphs)**：
  - 纯前端 SVG 矢量平滑绘制 `radiant_gold_adv` 与 `radiant_xp_adv` 曲线图与渐变面积图；
  - 标明 0 轴分界线（上方绿色天辉优势，下方红色夜魇优势），鼠标 Hover 实时显示指定分钟具体领先值与极值转折点。
- **Tab 3: 【高阶攻防与视野贡献】(Advanced Stats & Wards)**：
  - 视野攻防对比：真眼购买/插眼数 (`sen_placed`)、假眼购买/插眼数 (`obs_placed`)、宝石；
  - 野区与资源掌控：拉野堆叠数 (`camps_stacked`)、控符数 (`rune_pickups`)；
  - 生存与买活：买活次数 (`buyback_count`) 与受损分析。
- **Tab 4: 【BP 禁选与加点路线】(Draft & Ability Builds)**：
  - 若对局存在 `picks_bans`，按官方时间轴顺位展示天辉夜魇双方的 Ban / Pick 英雄列表；
  - 展现选手技能升级加点时序路线。

## 曾考虑的替代方案

### 1. 采用弹窗 Modal 或侧滑抽屉 Drawer 展示详情
- **为何最强**：不需要切换路由或隐藏列表，轻量浮层即可关闭。
- **为何放弃**：Dota 2 的单场战局数据量极大（十人完整 10 格物品、KDA、伤害、经济、经验走势图、BP 及 AI 复盘报告）；在弹窗或抽屉的狭窄受限空间内浏览体验极为逼仄拥挤，无法实现电竞级的全景大盘沉浸感；全屏独立详情页配合极速返回是行业最佳实践。

### 2. 将走势图通过第三方重型图表库（如 ECharts）渲染
- **为何最强**：ECharts 功能全面，开箱即用各种动画与交互。
- **为何放弃**：ECharts 打包体积增加 1~2MB，不符合神盾教练极轻原生架构铁律；手写轻量 SVG 折线/面积图仅百行代码，体积不到 5KB，完全满足 60fps 丝滑交互与暗黑电竞 HUD 主题自适应。

## 后果与验证计划

- **正面收益**：
  - 赛后复盘页面结构清晰，解决了长页面上下滚动的体验痛点；
  - 对局数据库粒度达到专业电竞级（涵盖背包物品、推塔伤害、治疗量、视野、团队走势图与 BP）；
  - AI 复盘入口突出，操作直观高效。
- **验证计划**：
  - 运行 `npm run verify-notes` 校验笔记结构；
  - 针对无对局、有对局、各种游戏模式（含无 BP、无走势图的非天梯局）做全面数据容错守卫验证；
  - 运行前端 `pnpm build` 与打包验证，确保零 TypeScript 报错。
