# Agent Note: 127 英雄静态权威常数与官网物品分层网格规范

Status: implemented
Date: 2026-09-20
Class: architecture

## 问题背景与因果机制分析

在 Dota 2 辅助工具中，英雄属性和物品图鉴是电竞玩家与 AI 战术推演的基石。在过往工程演进中经常出现以下几类致命数据退化：
1. **英雄基础属性计算公式失真**：Dota 2 官方 Datafeed 中给出的力量、敏捷、智力已包含 1 级成长度，而基础护甲与攻击力需要结合主属性进行换算。如果直接使用粗糙的静态字段或第三方非标准公式，会导致 1 级基础生命、攻击力与护甲严重失准；
2. **技能模板占位符裸露与旧升级幽灵**：官方 JSON 中存在大量 `%damage%`、`%duration%`、`{s:bonus_*}` 等模板宏；在技能重做后，官方往往只将 `ability_has_scepter` 设为 `false`，却遗漏了清理 `scepter_loc`，导致界面出现过时废弃升级或暴露难看的未解析宏代码；
3. **物品图鉴混乱与废弃物露头**：遍历未过滤的原始物品库会导致已删除的旧版装备（如铁意头盔旧模板、测试小件）混入图鉴，且分类缺乏官网层级感，破坏电竞查阅效率。

## 决策方案

确立 **127 英雄权威常数底线、动态技能宏替换与官网物品标准分层网格**：

1. **127 英雄 100% 权威常数与属性公式**：
   - 127 位英雄中文名与主属性在 `heroNames.ts` 中 100% 静态常数兜底；
   - 彻底修复规范文档 `docs/HERO_AND_ITEM_DATA_SPEC.md` 中的错位缺陷（排除旧版从 78 酒仙开始的错位与幻觉名称），确保 ID、英文 internal slug 与官方中文名 100% 精确契合；
   - 严格遵守 1 级基础属性官方换算公式：
     - `1 级力量 = 基础力量 + 1 级力量成长`；
     - `1 级生命值 = 120 + 力量值 * 22`；
     - `1 级魔法值 = 75 + 智力值 * 12`；
     - `1 级护甲 = 基础护甲 + 敏捷值 * 0.167`。

2. **多层级宏替换引擎 (`abilityTextResolver.ts`) 与六状态分类**：
   - 建立优先级宏替换机制：神杖/魔晶专属值 > `special_values` > 别名公式 > 天赋 ID 反向关联动态补值；
   - 彻底清洗 HTML 标签与多余首尾空格，严禁将裸露宏字符串（如 `{s:bonus_radius}`）直接暴露给用户或 AI；
   - 确立以 `ability_has_scepter` / `ability_has_shard` 为唯一的法定标志，严格过滤并屏蔽已重做或失效的历史旧升级模板。

3. **官网物品分层网格与视口自适应悬浮卡片**：
   - 严格按照官方 10 大分类组织物品：基础（消耗品、属性、装备、杂项、神秘商店）、升级（辅助、法术、防御、武器、神装）以及中立生物道具；
   - 物品网格图标严格规范为官方标准比例 **56x42 像素**；
   - 物品悬浮提示卡（Tooltip）实现智能视口边缘碰撞检测与自动翻转，防止超出屏幕视口造成信息截断。

4. **架构纯洁性与前后端边界纠偏（清理伪问题与 C# 遗留）**：
   - 彻底清理跨文件规范中残留的 C# 伪概念（如 `Assets/Data/` 路径、`Dictionary<...>` 类型、`DotaAliasTable.cs` 伪文件及取消令牌）；
   - 纠正对 Go 语言与 UI 交互的认知错位：Go 后端专职处理 GSI 4444 原生网络监听与系统级调用，完全不参与前端 UI 控件渲染与键盘输入事件分发；
   - 清理过时的“TitleBar 专有拖拽区与打字穿透竞争”及“IME 输入法防反弹保护”等非真实痛点：主窗口使用 Windows 原生深色沉浸式标题栏（`Frameless: false`），由操作系统直接接管窗口拖拽；独立悬浮窗虽为无边框但纯只读无输入框，杜绝无意义过度设计。

## 曾考虑的替代方案

### 1. 运行时通过爬虫实时抓取 Liquipedia
- **最强理由**：文本解释详尽，社区修正及时。
- **为何弃用**：网络请求具有不可靠性（如反爬拦截、网络延迟、高并发限流），严重违背离线可靠性与秒级响应原则；本地静态权威快照兜底才是电竞软件的立足之本。

### 2. 遇到未解析占位符时直接用正则表达式将其删除
- **最强理由**：界面不再显示难看的 `%key%` 英文。
- **为何弃用**：删除宏会掩盖数值缺失的事实，使一句话变成缺少主语或宾语的语病文本。显式补全参数或进行合理解析才是正道。

### 3. 保留 TitleBar 拖拽区与 IME 防反弹作为所谓的“前瞻性防御规范”
- **最强理由**：未来若主窗口改成无边框自定义标题栏，可能会需要这些机制。
- **为何弃用**：脱离实际运行架构的“幽灵防御”会导致团队认知混乱，误以为 Go 语言或当前 Vue 3 架构存在输入法打断缺陷。坚守契约事实，只保留与当前架构严丝合缝的真实规范。

## 后果与验证计划

- **收益**：全英雄 127 位数值与文档名录 100% 精确可信，架构事实边界清晰纯粹，无废弃装备与旧框架概念干扰。
- **验证**：执行 `node scripts/test-hero-and-item-spec.cjs` 与 `node scripts/generate-hero-text-audit.cjs`，确保 127 位英雄基础属性与全技能解析缺项为 0；执行 `npm run verify-notes` 确保决策笔记格式完全合规。
