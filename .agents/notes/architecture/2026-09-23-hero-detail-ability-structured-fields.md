# Agent Note: 英雄详情技能面板补齐官网结构化字段与背景介绍

Status: implemented
Date: 2026-09-23
Class: architecture

## 问题背景与因果机制分析

用户最初以力丸（Riki）为例提出需求，后续明确要求**放大到全部英雄、落地在英雄详情页（hero 页面）**，而非单个英雄。核查后发现**根因不是「数据缺失」，而是「数据未被消费」**，完整因果链如下：

1. **数据层无缺口**：项目内置快照 `frontend/public/assets/data/heroes-details-official.json`（`source: https://www.dota2.com.cn/datafeed/hero`）与官网实时接口 `https://www.dota2.com.cn/datafeed/hero?hero_id=32` 逐字段 diff，`abilities` 完全一致，唯一差异是 `update_time`（1789624862 → 1790128835）。说明技能名称与数值本来就是最新的。
2. **真正的缺口在渲染层**：`HeroesView.vue` 的技能面板只渲染了名称、冷却 / 魔耗、描述宏、神杖 / 魔晶、机制注解与实战要领，**完全没有消费**三个已存在的官方字段——`behavior`（技能类型）、`special_values[].heading_loc`（各等级数值）、`lore_loc`（背景介绍）。因此若只在数据层补字段，UI 上不会出现任何变化。
3. **真实的数据缺口只有一个面**：全量 734 技能中 **621 个**官网自带 lore 原文，**113 个**（覆盖 **103 个**英雄）官网 `lore_loc` 为空字符串。这是唯一需要项目自己产出文案的地方。

结论：必须「渲染层补齐（全英雄数据驱动）+ 数据层只补官网真空缺（113 条）」，二者缺一不可。

## 决策方案

1. **新增 `frontend/src/utils/abilityMeta.ts`（官方枚举解码器）**
   - `behavior` 用 **BigInt 按位解码**：官网 behavior 是 64 位标志字符串，用 Int32 会溢出成负数导致技能类型全部错判（呼应 [docs/OFFICIAL_HERO_DATA.md](docs/OFFICIAL_HERO_DATA.md) 的「不可用 Int32」约束）。只收录官网会展示的已知低位；主类型（被动 / 切换 / 单位目标 / 点目标 / 无目标）互斥取优先级最高的一个，附加特性（持续施法 / 范围 / 瞬间施法 / 自动施放）并列展示。
   - `damage` / `immunity` / `dispellable` 严格按文档面板口径映射；**未知枚举统一输出「资料待同步」，绝不默认成「否」**（零伪造原则）。
   - `getAbilityLevelValues()` 只取 `heading_loc` 非空的 `special_values`——无中文标签的内部键（如 `AbilityCastRange`、`AbilityCooldown`）一律不展示，避免英文污染 UI；全 0 的官网占位行跳过；各等级数值完全相同时折叠为单值，对齐官网「减速持续时间 0.75」的展示口径。部分官网标签自带 `<font>` 着色（如「`<font>眩晕</font>`时间」），模板统一过 `cleanHtml` 再展示。

2. **新增 `frontend/src/data/abilityLore.ts`（背景介绍解析器）**
   - `resolveAbilityLore()` **官网 `lore_loc` 原文绝对优先**，禁止改写、扩写或套用其他版本译文；官网缺失时才回落到 `ABILITY_LORE_SUPPLEMENT` 的项目自撰文案，并返回 `source: 'project'` 供 UI 显式标注「项目补充」，**绝不冒充官网原文**。
   - **全量补齐 113 条官网缺失 lore**：`ABILITY_LORE_SUPPLEMENT` 覆盖 **103 个英雄的 113 个技能**（百戏大王 5 件纪念品、艾欧 3 个幽魂切换、巫医 / 修补匠 / 矮人直升机 / 琼英碧灵各 2 个），按英雄 ID 顺序组织并逐条注释，便于官网补齐原文后精准删除。
   - 补充文案写作口径与官网力丸 lore 一致：第三人称、单句、克制、不解释机制、**不出现任何数值**（数值一律由各等级数值表承载，避免文案与数值双源冲突）。

3. **`HeroesView.vue` 渲染层补齐**：技能名旁追加技能类型标签；描述下方依次渲染「背景介绍」「技能类型 / 伤害类型 / 无视减益免疫 / 可以驱散」「各等级数值」三块。全部由官方数据驱动，对 127 个英雄同时生效，**不是力丸专属硬编码**。

## 曾考虑的替代方案

- **直接改写 `heroes-details-official.json` 注入中文派生字段**：最强的理由是改动面最小、不需要新增解析层。放弃的原因是该文件是官网 datafeed 的原始快照（自带 `source` 与 `fetched_at`），混入派生字段会污染「单一事实来源」，且下次刷新快照即被覆盖丢失，与仓库既有的事实来源一致性约束冲突。
- **为力丸单独写一份硬编码技能详情数据**：最强的理由是交付最快、文案完全可控。放弃的原因是它会与官网快照形成双源，版本更新后必然劣化产生错误数值，违反零伪造原则与全英雄一致渲染原则。
- **官网缺失的 lore 直接留空不展示**：最强的理由是最保守、零风险。放弃的原因是用户明确要求全英雄每个技能都有背景介绍；最终改为「官网原文优先 + 项目补充并显式标注来源」，同时满足诉求与合规。
- **把 113 条补充文案写进官方快照 JSON**：最强的理由是与现有技能数据同处一处、无需新模块。放弃的原因同样是污染 datafeed 原始快照、刷新即丢失，且文案与数据混在一起无法区分来源。

## 后果与验证计划

**正面收益**：英雄详情页首次完整呈现官网技能详情口径的 4 项结构化属性与各等级数值；背景介绍首次上屏，且 **734 / 734 = 100%** 技能都有背景文案（621 条官网原文 + 113 条项目补充），127 个英雄全部覆盖。

**代价与约束**：`behavior` 只解码官网会展示的已知低位，未收录的高位（如先天技能携带的 2^49 标记）被静默忽略；`special_values` 中没有中文标签的条目不展示（如敌法师「闪烁」无各等级数值行，整块隐藏），若官网后续补标签会自动生效；113 条补充文案是项目自撰，需随官网补齐原文而清理。

**验证**：
1. `vite build` 全量构建通过、eslint 干净（铁律第 15 条；注意 `npm run build` 走 pnpm 在本沙箱会挂起，直接跑 vite 即可）。
2. 官网实时接口 `?hero_id=32` 与内置快照逐字段 diff，`abilities` 完全一致。
3. 力丸五技能解码结果核对：烟幕 = 点目标 · 范围；闪烁突袭 = 单位目标；绝杀秘技 = 点目标 · 范围 · 持续施法；背刺 = 被动；刀光谍影 = 被动。与官网「技能：点目标」一致。
4. **覆盖率回归**：734 技能中官网原文 621、项目补充 113，缺失 0、冗余补充键 0，覆盖率 100%。
5. 抽查敌法师 / 巫医 / 百戏大王 / 艾欧渲染结果正常，官网 `<font>` 标签经 `cleanHtml` 后正确显示为「眩晕时间」等纯文本。
