# Agent Note: 游戏状态集成 (GSI) 零模拟数据守卫与非外挂合规基线

Status: implemented
Date: 2026-09-20
Class: architecture

## 问题背景与因果机制分析

在 Dota 2 辅助工具开发与运行中，容易出现两大严重风险：
1. **合规红线与封号风险**：任何读取游戏内存、注入 DLL、Hook DirectX/Vulkan 渲染或模拟鼠标键盘点击的行为，均严重违反 Valve Anti-Cheat (VAC) 协议，会导致玩家账号面临 VAC 永封。
2. **开发期测试数据污染生产环境（伪造数据幻觉）**：以往开发调试中若在生产上下文中注入“假敌法师”、“假战局快照”等预设模拟数据，会导致用户在非游戏状态下看到虚假战况，产生误导并破坏系统的真实性与可信度。

## 决策方案

确立**官方 GSI 接入、非外挂合规与绝对零伪造模拟数据**的最高工程红线：

1. **绝对合规红线（非外挂原则）**：
   - 严禁读取 Dota 2 进程内存；
   - 严禁向游戏进程注入任何 DLL 或修改执行指令；
   - 严禁 Hook 游戏图形渲染管线；
   - 严禁模拟任何键盘、鼠标或快捷键输入；
   - 唯一的对局数据通道是监听 Valve 官方提供的 Game State Integration (GSI) 本机 HTTP POST（默认端口 `4444`）。

2. **零伪造模拟数据原则（Zero-Mock Guard）**：
   - 实时教练、战况看板与桌面悬浮窗严禁在未建立真实对局连接时伪造任何虚拟英雄（如预设敌法师、假英雄状态等）；
   - 当游戏未连接、对局未开始或英雄未就绪时，界面必须呈现真实的“等待 GSI 4444 端口接入”空态守卫；
   - 开发调试专用的模拟器（`GsiSimulator.vue`）必须处于独立隔离的调试入口，绝对不允许污染生产环境的默认数据流。

3. **确定性规则优先与秒级无缝降级**：
   - 战术告警判定（肉山刷新、神符刷新、血蓝低危、被控状态等）由 100% 确定性本地代码逻辑裁定，实现 0ms 响应；
   - AI 模型仅作为可选的辅助解释，当 AI 离线或超时时，确定性规则原文无缝呈现，系统功能不受任何影响。

## 曾考虑的替代方案

### 1. 默认展示一套“演示战局数据”让界面看起来丰满
- **最强理由**：玩家在刚打开客户端且未进游戏时，界面看起来充实，不会显得空旷。
- **为何弃用**：严重违背战术工具的严谨性，容易让玩家误以为该数据为真实对局，甚至误导其操作。真实、干净的“等待接入”空态才是生产级电竞工具的唯一标准形态。

### 2. 通过注入 DirectShow / 游戏 Hook 获取高频视角数据
- **最强理由**：能获取更多小地图、非选定单位和视野之外的信息。
- **为何弃用**：触碰 Valve VAC 反作弊法律与技术红线，直接导致玩家封号，坚决禁止。

## 后果与验证计划

- **收益**：100% 安全合规，玩家可长期放心使用；系统状态真实透明，杜绝数据污染。
- **验证**：断开游戏连接启动客户端，验证实时教练页与悬浮窗均稳定停留在“等待 GSI 4444 端口接入”状态，无任何虚拟英雄或假数据泄露。
