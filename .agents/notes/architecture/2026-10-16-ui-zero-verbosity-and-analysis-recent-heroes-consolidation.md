# Agent Note: 全面践行 UI 零废话极简铁律与赛后分析近期英雄下沉收敛

Status: implemented
Date: 2026-10-16
Class: architecture

## 问题背景与因果机制分析

1. **界面多余副标题、说明性段落与营销词汇残留**：
   - 违规表现：在部分业务视图中仍残留有修饰性长句与副标题，例如：
     - `CoachView.vue` 标题栏旁带括号副标题 `(10Hz GSI 毫秒快照实时主动裁定 · 纯自主战术流)`；
     - `VoiceBroadcastSection.vue` 中 9 类战术提醒卡片渲染了冗余的 `cat.description` 描述文本（如“对线期破塔转线、抱团控图压制、上高与撤退大局把控”等解释性段落），并在试听按钮旁渲染了“内置原生离线 MeloTTS 引擎”说明标签；
     - `ThreeSegmentToggle.vue` 原生 title 属性中嵌套了“（屏幕气泡 + MeloTTS 超保真朗读）”等技术黑话；
     - `MatchupRecommendationPanel.vue` 中渲染了“大数据动态出装 · 实战针对推荐”冗余修饰及“OpenDota 高分段大数据”次级徽标。
   - 根因机制：开发演进过程中，为解释底层技术机制（10Hz GSI、MeloTTS、OpenDota 算法），在 DOM 中塞入了副标题和说明段落，直接违反了 AGENTS.md 核心铁律第 11 条【UI 零废话与 DOM 极简铁律】。

2. **赛后分析页面指标冗余与近期英雄卡片过于局促**：
   - 违规表现：此前 `PlayerProfileBanner.vue` 渲染了 6 个指标（含推塔伤害、样本场次、战损比率），导致横向挤压；下方近期英雄卡片尺寸极小（微型缩略图，高度过矮、字号极小），视觉辨识度差且点击困难；
   - 顶栏噪音：顶部存在多余的搜索框与刷新按钮，赛后分析页面顶部还突兀摆放了 `MatchSearchBar`，违背了电竞看板的沉浸专注原则。

3. **实时教练接入对局空态卡片与对战识别风格割裂**：
   - 违规表现：未接入真实对局时，页面呈现大号虚线边框卡片，带有大图标与长段说明文字，与上方的赛前 BP 对战识别卡片（`border-slate-700/60 bg-slate-900/85 backdrop-blur-md rounded-xl`）在材质、间距与圆角上严重割裂。

4. **时间类事件提前预警阈值硬编码**：
   - 违规表现：河道神符、智慧神符、痛苦魔方等刷新预警时间被硬编码为 15 秒/18 秒，无法满足不同分段或选手风格的个性化控符战术节奏。

## 决策方案

1. **顶栏彻底去除与内容卡片整体上移顶格**：
   - `App.vue`：在 `/coach` 与 `/analysis` 下彻底隐藏带搜索框的全局 `TitleBar`；
   - `CoachView.vue` 与 `AnalysisView.vue` 内部顶部状态栏继承 `--wails-draggable: drag` 并挂载可复用的 `WindowControls.vue`（最小化/最大化/关闭），业务大卡片直接置顶顶格，空间利用率拉满。

2. **等待对局接入合并至对战识别卡片**：
   - 彻底删除教练主页独立的“等待对局接入”空态卡片；
   - 将已绑定选手信息（小头像、名字、ID）与对局接入指示器合并进 `BpVisionCaptureCard.vue` 头部左上角；
   - 未接入时呈现暗黄色等待接入状态与微脉冲图标；真实 GSI 连接建立后，接入图标与状态条自动变绿（`text-emerald-400`），实现赛前 BP 到实战 HUD 的极简自然演进。

3. **赛后分析恢复个人信息刷新按钮**：
   - `PlayerProfileBanner.vue` 顶部选手信息栏恢复“刷新战绩”按钮（带转动动画），并在 `AnalysisView.vue` 挂接重新拉取 OpenDota 战绩与个人主页的逻辑，满足选手赛后手动触发同步的需求。

4. **各时间类事件独立提前提醒时间配置 (0s - 30s/60s)**：
   - `AppSettings` 增加 `reminder_advance_seconds?: Partial<Record<ReminderCategoryKey, number>>`，赋予神符（`rune_control`）、痛苦魔方（`tormentor_tactics`）、肉山（`roshan_tactics`）各自分离的提前秒数控制；
   - `VoiceBroadcastSection.vue` 仅在时间敏感类卡片内渲染独立的秒数滑块，触发徽章实时联动显示秒数；
   - `gsiRuleEngine.ts` 动态从 store 读取各分类对应的独立秒数计算触发区间。

5. **前序工程资产解构沉淀 (`docs/DOTA2_MENTOR_PACK_REFERENCE.md`)**：
   - 全面解构 `dota2-mentor-pack-202608041148`，系统梳理 Electron+Node.js、YOLOv8 槽位推断、小地图 17 通道特征热图模型、STRATZ `curl.exe` 绕防爬代理、电竞黑话双向词典、GSI 心跳看门狗等机制，形成永久性工程参考文档。

## 曾考虑的替代方案

1. **方案 1：保留顶部搜索框，但仅在获得焦点时弹出**：
   - *最强理由*：不完全删除功能，用户需要检索比赛 ID 时仍可唤起。
   - *为什么不用*：电竞教练主场景是自动感应对局与自动化战绩画像，比赛 ID 搜索属于低频小众入口；在教练与赛后分析强行放置搜索框不仅污染视觉，还分散注意力，彻底隐藏最干净。
2. **方案 2：将推塔伤害和战损比率折叠为“更多指标”二级菜单**：
   - *最强理由*：兼顾需要查看微观数据的硬核用户。
   - *为什么不用*：违背 AGENTS.md 极简铁律；次级折叠层增加了 DOM 复杂度与交互负担，直接裁减出胜率、KDA、GPM 即可 100% 满足赛后第一眼战术定性。
3. **方案 3：全局使用统一提前提醒秒数滑块**：
   - *最强理由*：配置项少，界面最省空间。
   - *为什么不用*：神符（2/4/6/7m）与痛苦魔方（20m）的战术节奏完全不同；控符需要提前 10~15 秒推线集结，控魔方需要提前 20~25 秒开雾，全局统一秒数无法满足精细化战术要求，卡片内独立滑块才是最合理的粒度。

  - 对局接入状态与对战识别合二为一，左上角绑定信息清晰，接入后图标变绿，零多余空态；
