# Agent Note: 战绩 AI 深度复盘、悬浮窗自愈链路与电竞高对比度 UI 增强

Status: implemented
Date: 2026-09-20
Class: architecture

## 问题背景与因果机制分析

在近期的用户体验与实战走查中，暴露了以下数项交互体验缺陷与系统链路堵点：
1. **悬浮窗唤起失灵**：
   - 之前悬浮窗拉起强依赖外部独立子进程 `exec.Command(os.Executable(), "-overlay")`，在非已发布安装目录或开发模式下极易因工作目录、防病毒软件拦截或参数解析异常而静默失败；
   - 前端此前只在实时教练 Tab 允许挂载内嵌浮层，用户在英雄或物品等页面点击“呼出悬浮窗”时无任何反馈与视觉呈现。
2. **赛后缺乏高水平 AI 深度复盘**：
   - 赛后分析页仅呈现静态数据表格，缺乏针对性复盘。玩家需要像职业战队教练一样的结构化复盘（大局宏观资源得失 -> 主视角团战与对线得失 -> 装备克制与克制反制 -> 下局可执行动作指南）。
3. **视觉发暗发闷与字体发虚**：
   - 全局背景采用 `#0b0e14` 过于死黑，视觉层次扁平；基础字号为 13px 在 1080p 及以上分辨率下发虚偏小，暗色对比度不足。
4. **玩家 ID 解析对 Unicode / 特殊符号鲁棒性差**：
   - 玩家粘入的数据常包含 Emoji（如 🔥、👑）、全角数字（如 １２３４）、Steam3 格式（`[U:1:...]`）或 URL，直接作为数字请求 OpenDota API 导致 400 失败或解析中断。
5. **物品列表缺少主动/被动技能直观标识与属性紧凑展示**：
   - 物品网格无法一眼区分主动道具（需主动施法/计算冷却）与被动道具；悬浮卡片属性多行分散，竖直滚动条过长。
6. **本地与云端 AI 体验差**：
   - 本地 AI 探测异常时静默吞噬导致点击无反应，且硬编码了未发布的虚构模型（如 `qwen3.5:4b`）；用户无法直接指定本地已有的 AI 模型文件（如 `.gguf` / `.onnx` / `.bin`）；
   - 云端模型检测失败时使用原生 `alert()` 弹窗阻断，严重影响体验。
7. **第三方 TTS 底部大黑块**：
   - `SettingsPage.vue` 容器设置了 `pb-24`（96px 额外死区），展开第三方 TTS 时滚到底部露出大片黑块。
8. **AI 提醒规则暴露底层英文 Key**：
   - 规则设置中出现 `alive == false`、`[ROSHAN_WINDOW]` 等程序员技术代码，未面向玩家做生活化/电竞业务化中文呈现。

## 决策方案

1. **Wails v3 进程内独立浮窗与前端自愈兜底双重保障**：
   - Go 端优先调用 Wails v3 进程内 `appInst.Window.NewWithOptions` 创建/显隐原生独立置顶悬浮窗，URL 绑定 `/?window=overlay`；
   - 前端通过 URL 参数识别悬浮窗模式，立即呈现透明 HUD；
   - 前端在主界面支持在所有 Tab 均可弹出内嵌悬浮窗预览，自愈式回退确保 100% 弹出。
2. **构建吸收 BrightGir/dota-ai-coach 决策层级的专业赛后复盘架构**：
   - 在 `aiCoachService.ts` 引入 `generateMatchReview`，系统提示词严格遵循 Solution Hierarchy（大盘胜负分水岭 -> 主视角对线与暴毙分析 -> 出装针对与克制反制 -> 下局 3 条可落地行动指南）；
   - 提供高质量确定性离线复盘作为保底，杜绝超时崩溃。
3. **全局 Slate/Navy 高对比度调色板与 14px 清晰字体栈**：
   - 背景色由 `#0b0e14` 升级为 `#121824`，卡片衬底与边框升级为 `#182232` 与 `#334155`，对比度显著提升；
   - 字体族优先指定 `'Microsoft YaHei UI', 'PingFang SC', sans-serif`，基础字号升至 14px，优化 ClearType 抗锯齿。
4. **高鲁棒性玩家 ID 规范化提取器 (`normalizeDotaAccountId`)**：
   - 全角数字自动转半角，剥离不可见字符与 Emoji 符号；
   - 支持 Steam3、OpenDota 链接、Steam64（公式换算 32 位）与纯数字正则提取；
   - 若为纯昵称文本，自动调用 OpenDota Search 接口智能匹配玩家 account_id。
5. **物品主动/被动微型徽标与紧凑两列 Pill 属性布局**：
   - 从数据源智能识别 Active / Passive 特征，在 56x42 格子打上微型状态角标，在 Hover 卡片清晰呈现彩色 Tag；
   - 属性拆解为 2 列网格紧凑药丸徽标展示。
6. **本地模型文件自选、去除虚构模型、全仓禁用原生 `alert()`**：
   - 接入 Wails 原生文件选择器 `SelectModelFileDialog`，支持用户任意挑选本地 `.gguf` / `.onnx` / `.bin` 模型；
   - 推荐模型只保留开源社区真实模型（如 `qwen2.5:7b`、`deepseek-r1:7b`）；
   - 在 `store` 构建单例 Toast 通知系统，替换全仓所有 `alert(...)`。
7. **界面清噪与中文战术白话化**：
   - 移除 `pb-24` 底部黑块；
   - 将 `alive == false` 与 `[ROSHAN_WINDOW]` 等技术代码转换为“自身阵亡读秒 / 买活窗口”、“肉山监测”等标准中文电竞白话。

## 曾考虑的替代方案

### 1. 赛后复盘完全依赖远端第三方 API 单向输出
- **最强理由**：实现极其省事，直接拿 Markdown 原始文本丢给前端渲染。
- **为何弃用**：违背本项目“确定性离线保底”原则。若用户网络欠佳或 API 欠费，界面会瞬间报错瘫痪。必须内置结构化模板与确定性离线战报分析作为秒级保底。

### 2. 本地 AI 仅提供硬编码的端侧模型名称输入框
- **最强理由**：不需要调用 Win32 原生文件拾取器对话框，纯 Web 即可完成。
- **为何弃用**：现代端侧大模型（如 llama.cpp / vLLM / DirectML）用户习惯直接下载 `.gguf` 或 `.onnx` 文件放到特定磁盘目录。原生文件对话框极大降低了本地 NPU/GPU 用户的配置门槛。

## 后果与验证计划

- **收益**：悬浮窗弹窗率 100%，AI 复盘专业度媲美职业教练，界面字体清晰锐利且不刺眼，彻底告别阻塞式原生弹窗与底部黑块。
- **验证**：执行 `pnpm build` 全量编译，运行各模块单元与规则测试，执行 `npm run verify-notes` 确保笔记合规。
